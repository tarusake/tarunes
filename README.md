# tarunes

tarunes is a NES-compatible hardware design written in Veryl. It includes a 6502-family CPU, NES-style PPU / APU, CPU and PPU buses, memory blocks, an HDMI 480p scaler, I2S audio output, and SFC controller input.

The current public version mainly targets Verilator + SDL2 simulation. It converts an iNES ROM into PRG / CHR HEX files, loads them into simulation memory, and displays either the internal 256x240 video output or the 720x480 HDMI output in an SDL2 window.

No commercial ROM files are included in this repository.

## Project Layout

```text
tarunes/
├── Veryl.toml          # Veryl project configuration
├── Makefile            # Build, ROM conversion, and simulation targets
├── nes2hex.py          # Convert an iNES ROM into PRG / CHR HEX files
├── csv_to_opcodenotrace.py
│                       # Extract PC/opcode rows from a Gowin CSV trace
├── collapse_cpu_trace_loops.py
│                       # Collapse long wait loops in CPU traces
├── src/
│   ├── top.veryl       # Top-level module
│   ├── cpu.veryl       # CPU core
│   ├── ppu.veryl       # Picture Processing Unit (PPU)
│   ├── apu.veryl       # Audio Processing Unit (APU)
│   ├── i2s.veryl       # I2S transmitter
│   ├── hdmi_480p_scaler.veryl
│   │                   # Convert 256x240 video to 720x480 HDMI timing
│   ├── sfc_controller.veryl
│   │                   # SFC controller polling
│   ├── controller.veryl # $4016/$4017 controller registers
│   ├── oam_dma.veryl   # $4014 OAM DMA
│   ├── bus_cpu.veryl   # CPU bus decoder
│   ├── bus_ppu.veryl   # PPU bus decoder
│   ├── bus_if.veryl    # Bus interface
│   ├── memory.veryl    # Memory module
│   ├── tb_top.sv       # SystemVerilog testbench
│   └── tb_top.cpp      # C++ Verilator testbench driver
├── target/             # RTL generated by Veryl
└── obj_dir/            # Verilator build output
```

## Requirements

- [Verilator](https://www.veripool.org/verilator/) 5.0 or later
- [Veryl](https://github.com/veryl-lang/veryl) 0.20.1
- SDL2 development package (`sdl2-config`)
- SDL2_image development package (`SDL2_image.pc` visible to `pkg-config`)
- GNU Make
- GCC or Clang with C++17 support

Example for Ubuntu / Debian:

```bash
sudo apt install verilator libsdl2-dev libsdl2-image-dev make g++
```

### Installing Veryl

Veryl can be installed with `verylup`, the official Veryl toolchain installer. This project currently uses Veryl `0.20.1`.

Using Cargo:

```bash
cargo install verylup
verylup setup
verylup install 0.20.1
verylup default 0.20.1
veryl --version
```

`verylup setup` is only needed for the first installation. If `veryl --version` reports `veryl 0.20.1`, the toolchain is ready.

To update the installed toolchain:

```bash
verylup update
```

You can also install `verylup` by downloading a binary from its release page and placing it somewhere in your `PATH`. See [verylup: Veryl toolchain installer](https://veryl-lang.org/blog/verylup-veryl-toolchain-installer/) for details.

## Build

Place `<ROM name>.nes` at the repository root and run `make`.
By default, the build expects `helloworld.nes` and generates `helloworld_prg.hex` and `helloworld_chr.hex`.

```bash
make
```

To use another ROM, pass its basename through `ROM`:

```bash
make ROM=sample
```

This converts `sample.nes` into `sample_prg.hex` and `sample_chr.hex`, then passes them to Verilator through the `PROM_PATH` and `CROM_PATH` parameters.

To build with the APU disabled:

```bash
make ENABLE_APU=0
```

## Simulation

Build and run the simulator:

```bash
make run
```

The simulator opens an SDL2 window and displays the internal 256x240 video output at 2x scale. A normal run also prints a CPU trace and writes `wave.vcd`, which can be inspected with tools such as GTKWave.

For a faster run without the CPU trace or VCD output:

```bash
make run ARGS=--fast
```

Run another ROM:

```bash
make run ROM=sample
```

Stop after a fixed number of frames:

```bash
make run ARGS="--fast --frames 10"
```

Capture the HDMI 480p output instead of the internal 256x240 output:

```bash
make run ARGS="--fast --capture-hdmi --frames 10"
```

Runtime options:

- `--fast`: Disable CPU trace and VCD output
- `--capture-hdmi`: Display and save the 720x480 HDMI output
- `--frames N`: Stop after N completed frames
- `--dump-audio PATH`: Set the WAV output path
- `--dump-vram PATH`: Dump VRAM when the simulator exits
- `--log-ppu-writes PATH`: Log `$2006` / `$2007` writes
- `--dump-state`: Print a small PPU / WRAM state dump on exit

On exit, the simulator writes the last video frame to `last_frame.png` and audio to `apu.wav`.

Clean generated files:

```bash
make clean
```

## ROM Conversion

NES ROM files (`.nes`) can be converted into HEX files for simulation memory:

```bash
./nes2hex.py <input.nes>
```

Example:

```bash
./nes2hex.py helloworld.nes
```

Outputs:

- `helloworld_prg.hex`: PRG ROM for the CPU side
- `helloworld_chr.hex`: CHR ROM for the PPU side

For CHR RAM cartridges, no `*_chr.hex` file is generated because the ROM does not contain CHR ROM data.

## PPU

`src/ppu.veryl` provides:

- Background rendering
- Basic scroll register behavior (`v` / `t` / `w` / fine X)
- 8x8 sprite rendering through `$2003` / `$2004` OAM access
- `$4014` OAM DMA from WRAM to OAM
- VRAM / CHR ROM access control
- Palette RAM and NES palette based RGB output
- Video timing generation
- NMI / vblank / sprite zero hit

CPU-side VRAM and Palette RAM access is done through `$2006` / `$2007` style registers. Sprites are written into internal OAM through `$2003` / `$2004` style registers, then combined with background pixels in the PPU rendering path. The rendering path reads CHR ROM and VRAM, then the top-level module produces both the internal palette index and HDMI RGB output.

The current sprite implementation supports 8x8 mode, transparent pixels, sprite palettes, horizontal and vertical flipping, background priority, and sprite zero hit. `$4014` OAM DMA supports WRAM (`$0000-$1FFF`) as the transfer source, but the exact 513/514-cycle timing difference is not implemented. 8x16 sprites and sprite overflow are not implemented yet.

## CPU

`src/cpu.veryl` implements the main official 6502-family opcodes needed by the current design:

- Load / store: `LDA`, `LDX`, `LDY`, `STA`, `STX`, `STY`
- Arithmetic / logic: `ADC`, `SBC`, `CMP`, `CPX`, `CPY`, `AND`, `ORA`, `EOR`, `BIT`
- Shift / rotate / increment: `ASL`, `LSR`, `ROL`, `ROR`, `INC`, `DEC`, `INX`, `INY`, `DEX`, `DEY`
- Branch / jump / subroutine: `BCC`, `BCS`, `BNE`, `BEQ`, `BPL`, `BMI`, `BVC`, `BVS`, `JMP`, `JSR`, `RTS`, `RTI`, `BRK`
- Stack / transfer / flags: `PHA`, `PLA`, `PHP`, `PLP`, `TAX`, `TXA`, `TAY`, `TYA`, `TSX`, `TXS`, `SEI`, `SEC`, `CLI`, `CLD`, `CLC`, `SED`, `CLV`, `NOP`

Unimplemented opcodes are treated as `INVALID`. Unofficial opcodes are currently out of scope.

## APU / Audio

`src/apu.veryl` implements the basic registers and counters for two pulse channels, triangle, and noise. DMC is not implemented.

- `$4000-$4007`: pulse 1 / pulse 2
- `$4008-$400B`: triangle
- `$400C-$400F`: noise
- `$4015`: channel enable / status
- `$4017`: frame counter

The APU produces 8-bit samples. The top-level module stores them in a small FIFO, and `src/i2s.veryl` outputs them as I2S. The Verilator testbench can also save them as a WAV file.

## Video Output

`src/hdmi_480p_scaler.veryl` converts the 256x240 PPU output into a 720x480 HDMI 480p timing stream. In the Verilator testbench, `--capture-hdmi` captures frames from the HDMI-side RGB / sync / data-enable outputs.

## Memory Map

CPU side:

- `$0000-$1FFF`: WRAM
- `$2000-$2007`: PPU registers (`$2003`: OAMADDR, `$2004`: OAMDATA)
- `$4000-$4017`: APU / OAM DMA / controller registers
- `$4014`: OAM DMA, as part of `$4000-$4017`
- `$4016-$4017`: controllers
- `$8000-$FFFF`: PRG ROM

PPU side:

- `$0000-$1FFF`: CHR ROM
- `$2000-$3EFF`: VRAM
- `$3F00-$3F1F`: Palette RAM
